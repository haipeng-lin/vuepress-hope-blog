## 核心概念

要理解上下文工程，首先要区分两种上下文类型及其对应的数据源

**上下文类型：**

| 类型           | 定义                       | 作用范围          | 典型操作                           |
| :------------- | :------------------------- | :---------------- | :--------------------------------- |
| **瞬态上下文** | LLM 在单次调用中看到的内容 | 单次模型调用      | 修改提示词、过滤消息、动态选择工具 |
| **持久上下文** | 跨轮次保存在状态中的内容   | 整个会话/生命周期 | 更新状态、写入长期记忆、日志记录   |

**数据源层级：**

- **运行时上下文 (Runtime Context)**：静态配置，会话范围（如：用户 ID、API Key）。
- **状态 (State)**：短期记忆，会话范围（如：当前消息历史、工具执行结果）。
- **存储 (Store)**：长期记忆，跨会话（如：用户偏好、历史摘要）。

## 实现机制

在 Spring AI Alibaba 中，通过 **Hook** 和 **Interceptor** 来实现对上下文的精细控制。

### 模型上下文

控制每次模型调用包含的内容（指令、历史、工具、模型本身、输出格式）。主要通过 `ModelInterceptor` 实现。

- 系统提示 (System Prompt)
  - **基于状态**：根据对话长度动态调整提示（例如：长对话时要求模型“保持简捷”）。
  - **基于存储**：加载用户长期偏好（如沟通风格、语言）注入提示词。
- 消息历史 (Messages)
  - **过滤**：使用 `MessageFilterInterceptor` 仅保留最近 N 条消息（注意：这只是临时过滤，不影响持久化状态）。
  - **摘要**：使用 `MessagesModelHook` 在 `BEFORE_MODEL` 阶段检测消息长度，若过长则生成摘要并替换旧消息（这是持久化修改）。
- 工具 (Tools)
  - **动态选择**：根据用户角色（Admin/User）动态决定 Agent 可见的工具列表。
- 模型 (Model)
  - **动态路由**：根据任务复杂度（如消息长度、关键词）选择简单模型或复杂模型。
- 响应格式 (Response Format)
  - 动态决定输出 Schema，强制模型按特定结构返回。

### 工具上下文

控制工具能访问和修改的数据。通过 `ToolContext` 对象传递。

- **读取状态**：工具可以通过 `toolContext.getContext().get("state")` 读取当前的 `OverAllState`（短期记忆）。
- **修改状态**：工具可以通过写入 `extraState`，将处理结果持久化到 State 中，供后续节点使用。

### 生命周期上下文

使用 `Hook` 在 Agent 生命周期的特定节点执行操作。

- Hook 位置
  - `BEFORE_AGENT` / `AFTER_AGENT`
  - `BEFORE_MODEL` / `AFTER_MODEL`
- 典型应用
  - **日志记录 (Logging)**：在模型调用前后记录状态。
  - **消息摘要 (Summarization)**：在模型调用前检查消息数量，如果超过阈值，调用摘要模型压缩历史，并使用 `UpdatePolicy.REPLACE` 替换消息列表。

## 关键代码模式

### **模式一：瞬态 vs 持久 更新**

- 瞬态更新 (Interceptor)
  - 场景：临时过滤消息、临时修改提示词。
  - 特点：只影响当前这一次 LLM 调用，**不改变** 状态中保存的历史数据。
- 持久更新 (Hook)
  - 场景：消息摘要、写入长期记忆。
  - 特点：永久修改 `State`，后续循环都能感知到变化。

### **模式二：工具中的状态交互**

```java
// 读取状态
OverAllState currentState = (OverAllState) toolContext.getContext().get("state");

// 写入状态 (持久化)
// extraState 中的值会被合并回 State
extraState.put("processed_data", processed);
```

### **模式三：消息摘要 Hook 逻辑**

1. **检查**：在 `BEFORE_MODEL` 阶段检查 `previousMessages.size()`。
2. **生成**：若超过阈值，调用摘要模型生成 `summary`。
3. **重组**：保留 `SystemMessage` + 新增 `UserMessage(摘要)` + 保留最近几条 `Messages`。
4. **替换**：返回 `AgentCommand` 并设置策略为 `UpdatePolicy.REPLACE`。
