## ReactAgent 理论基础

### 什么是 ReAct

ReAct（Reasoning + Acting）是一种将推理和行动相结合的 Agent 范式。在这个范式中，Agent 会：

1. **思考（Reasoning）**：分析当前情况，决定下一步该做什么
2. **行动（Acting）**：执行工具调用或生成最终答案
3. **观察（Observation）**：接收工具执行的结果
4. **迭代**：基于观察结果继续思考和行动，直到完成任务

这个循环使 Agent 能够：

- 将复杂问题分解为多个步骤
- 动态调整策略基于中间结果
- 处理需要多次工具调用的任务
- 在不确定的环境中做出决策

### ReactAgent 工作原理

Spring AI Alibaba 中的`ReactAgent` 基于 **Graph 运行时**构建。Graph 由节点（steps）和边（connections）组成，定义了 Agent 如何处理信息。Agent 在这个 Graph 中移动，执行如下节点：

- **Model Node (模型节点)**：调用 LLM 进行推理和决策
- **Tool Node (工具节点)**：执行工具调用
- **Hook Nodes (钩子节点)**：在关键位置插入自定义逻辑

## 核心组件

### 模型

以 `OpenAI`为例

```java
@Configuration
public class OpenAiConfig {

    @Bean
    public ChatModel openAiChatModel() {
        // 1. 创建底层 OpenAiApi 客户端
        OpenAiApi openAiApi = OpenAiApi.builder()
            .baseUrl("https://api.openai.com")
            .apiKey(new SimpleApiKey("your-api-key"))
            .build();

        // 2. 创建并返回 ChatModel
        return OpenAiChatModel.builder()
            .openAiApi(openAiApi)
            .defaultOptions(
            	OpenAiChatOptions.builder()
    		        .withTemperature(0.7)    // 控制随机性
		            .withMaxToken(2000)      // 最大输出长度
	    	        .withTopP(0.9)           // 核采样参数
            .build()
        )
            .build();
    }
}
```

### 工具

工具，Function Calling，用于弥补大语言模型（LLM）本身的局限性，赋予其获取实时信息和执行实际操作的能力

- **信息检索：**连接外部数据源，增强模型的知识储备
- **采取行动：**将模型的“计划”转化为实际的系统操作

以查询天气工具为例

1. 定义工具

   ```java
   @Component
   public class WeatherTools {

       @Tool(description = "查询指定城市的当前天气信息，返回温度、天气状况和风力")
       public String getWeather(@ToolParam(description = "城市名称，如：北京、上海") String city) {
           // 模拟数据
           Map<String, String> mockData = Map.of(
                   "北京", "晴天，温度 28°C，北风 3 级",
                   "上海", "多云，温度 31°C，东南风 2 级"
           );
           return mockData.getOrDefault(city, city + "：暂无天气数据");
       }
   }
   ```

2. 注册工具

   ```java
   // 在 Agent 中使用
   ReactAgent agent = ReactAgent.builder()
       .name("search_agent")
       .model(chatModel)
       .tools(WeatherTools)
       .build();

   // 在 ChatClient 中使用
   chatClient.prompt()
       .user(message)
       .tools(weatherTools)
       .call()
       .content();
   ```

### 系统提示词

系统提示词，System Prompt，是赋予 Agent “灵魂”和“规则”的关键

核心作用：

1. **角色定位**：明确 Agent 的身份和特色（例：“你是一位擅长说天气冷笑话的专业天气预报员”）。
2. **行为约束**：规定模型必须遵守的规则和逻辑顺序（例：“如果用户询问天气，必须先确认地点”）。
3. **工具说明**：清晰描述可用工具的功能，指导模型在何时、以何种顺序调用工具。
4. **输出规范**：约束模型回复的语气、格式或长度（例：“回答要简短”、“以 JSON 格式输出”）。

接入方式：在调用 `ReactAgent.builder()` 时，使用 `.systemPrompt` 接入

```java
ReactAgent agent = ReactAgent.builder()
    .name("my_agent")
    .model(chatModel)
    .systemPrompt("你是一个专业的技术助手。请准确、简洁地回答问题。")
    .build();
```

详细：

```java
String SYSTEM_PROMPT = """
    你是一位专业的行程规划助手。
    你可以使用以下工具：
    - get_weather_for_location：获取指定地点的天气
    - get_user_location：获取用户当前所在位置

    行为约束：
    1. 如果用户询问天气，必须先确认地点。
    2. 如果从问题中能判断出他们指的是自己所在的地方，必须先使用 get_user_location 获取位置，再查天气。
    3. 回答要尽量幽默风趣。
    """;

ReactAgent agent = ReactAgent.builder()
        .name("travel_agent")
        .model(chatModel)
        .systemPrompt(SYSTEM_PROMPT)
        .tools(getWeatherTool, getUserLocationTool)
        .build();
```

### 记忆

自定义记忆主要分为两种场景：一是**自定义记忆的存储介质**（例如将默认内存替换为 Redis 或 MySQL），二是**自定义记忆的处理策略**（例如对过长的对话进行修剪、总结或拦截）

#### 存储介质

默认情况下，Agent 使用内存存储，这在生产环境中会导致重启后记忆丢失。要接入自定义存储，需要实现对应的 `Saver` 接口

```java
// 注入 Redisson 客户端
RedisSaver redisSaver = new RedisSaver(redissonClient);
ReactAgent agent = ReactAgent.builder()
        .name("my_agent")
        .model(chatModel)
        .tools(getUserInfoTool)
        .saver(redisSaver) // 挂载自定义的 Redis 存储器
        .build();
```

#### 记忆处理策略

**自定义一个“修剪历史消息”的 Hook**。通过继承 `MessagesModelHook`，在模型思考前（`BEFORE_MODEL`）拦截消息列表，只保留最近的 N 条记录：

```java
@HookPositions({HookPosition.BEFORE_MODEL})
public class MessageTrimmingHook extends MessagesModelHook {
    private static final int MAX_MESSAGES = 10; // 限制最大消息条数

    @Override
    public String getName() {
        return "message_trimming";
    }

    @Override
    public AgentCommand beforeModel(List<Message> previousMessages, RunnableConfig config) {
        // 如果消息数量超限，只保留最近的 N 条
        if (previousMessages.size() > MAX_MESSAGES) {
            List<Message> trimmedMessages = previousMessages.subList(
                previousMessages.size() - MAX_MESSAGES,
                previousMessages.size()
            );
            return new AgentCommand(trimmedMessages);
        }
        return new AgentCommand(previousMessages); // 未超限则原样返回
    }
}
```

将 Hook 挂载到 Agent：

```java
ReactAgent smartAgent = ReactAgent.builder()
        .name("smart_memory_agent")
        .model(chatModel)
        .saver(new RedisSaver(redissonClient)) // 挂载 Redis 存储
        .hooks(new MessageTrimmingHook())      // 挂载自定义的记忆瘦身 Hook
        .build();
```

## 调用 Agent

当我们通过 `ReactAgent.builder()` 构建好智能体后，可以通过调用其提供的同步调用 `call()` 或流式调用 `stream()` 方法来触发执行。

### **同步调用**

只需要向 Agent 传入用户的提问（字符串或 `UserMessage` 对象），Agent 会自动执行“思考 -> 行动 -> 观察”的 ReAct 循环，直到得出最终答案并返回

```java

// 核心调用：直接传入用户问题
AssistantMessage response = weatherAgent.call(prompt);
// 返回 Agent 的最终文本回复
return response.getText();

```

支持的运行时配置，调用 call 方法时，传入 RunnableConfig 对象

```java
// 构建运行时配置，绑定会话 ID
RunnableConfig config = RunnableConfig.builder()
    .threadId(sessionId)
    .build();

// 将 prompt 和 config 一起传入
AssistantMessage response = weatherAgent.call(prompt, config);
return response.getText();
```

### 流式调用

使用 `stream()` 方法

```java
@GetMapping(value = "/stream-chat", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> streamChat(@RequestParam String prompt) {
    return weatherAgent.stream(prompt)
            .map(AssistantMessage::getText); // 提取文本内容并作为流返回
}
```
