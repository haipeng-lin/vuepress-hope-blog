## 前言

本篇记录 LangChain 1.x 快速开始的完整实现过程

官方文档：[LangChain Quickstart](https://docs.langchain.com/oss/python/langchain/quickstart)

本文使用阿里云百炼（DashScope）平台的 **deepseek-v4-pro-0813** 模型，
通过 OpenAI 兼容模式接入 LangChain。系统提示词、工具描述、用户消息全部使用中文。

### 核心概念

| 概念 | 说明 |
| --- | --- |
| `create_agent` | LangChain 1.x 统一的智能体创建入口 |
| `@tool` | 把普通 Python 函数包装成模型可调用的工具 |
| `system_prompt` | 约束智能体角色与行为 |
| checkpointer | 保存对话历史，实现多轮记忆 |
| `with_structured_output` | 让模型按 Pydantic schema 返回结构化对象 |

## 环境准备

### 安装依赖

```bash
pip install -U langchain
pip install -U langchain-openai
pip install -U langgraph
pip install python-dotenv
```

`langchain` 是核心包，`langchain-openai` 提供 `ChatOpenAI` 客户端，
`langgraph` 提供 checkpointer 等图执行能力。

### 配置 API Key

推荐直接使用系统环境变量：

```bash
export DASHSCOPE_API_KEY="sk-你的密钥"
```

也可以用 `.env` 文件，配合 `python-dotenv` 读取：

```python
from dotenv import load_dotenv

load_dotenv()
```

## 接入百炼 DeepSeek 模型

### 确认模型可用

百炼的 OpenAI 兼容模式提供了模型列表接口，可以先确认模型 ID 是否正确：

```bash
curl https://dashscope.aliyuncs.com/compatible-mode/v1/models \
  -H "Authorization: Bearer $DASHSCOPE_API_KEY"
```

返回的列表中包含 `deepseek-v4-pro-0813`，确认可用。

### 创建模型实例

百炼提供的是 OpenAI 兼容接口，所以直接用 `init_chat_model` 的 `openai:` 前缀：

```python
import os

from langchain.chat_models import init_chat_model

model = init_chat_model(
    "openai:deepseek-v4-pro-0813",
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    api_key=os.environ["DASHSCOPE_API_KEY"],
    temperature=0.3,
)
```

> [!WARNING]
> 不要同时传 `model_provider="openai"`。两种写法同时存在时，`openai:` 前缀不会被剥离，
> 最终模型名会变成 `openai:deepseek-v4-pro-0813`，请求直接返回 404：
>
> ```
> Error code: 404 - The model `openai:deepseek-v4-pro-0813` does not exist
> ```

### 深度思考模式

`deepseek-v4-pro` 默认开启深度思考（reasoning），响应里会多出 `reasoning_content` 字段，
并额外消耗 reasoning token：

```json
{
  "completion_tokens_details": { "reasoning_tokens": 134 }
}
```

不需要时可以通过 `extra_body` 关闭，响应速度会明显变快：

```python
model = init_chat_model(
    "openai:deepseek-v4-pro-0813",
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    api_key=os.environ["DASHSCOPE_API_KEY"],
    extra_body={"enable_thinking": False},
)
```

> [!NOTE]
> 深度思考模式下 `langchain-openai` 不会把 `reasoning_content` 提取到
> `content_blocks` 里，`additional_kwargs` 中也只有 `{"refusal": null}`，
> 思考内容仅体现在 token 用量统计中。

## 基础对话

最简形态就是一次 `invoke`：

```python
response = model.invoke(
    [
        {"role": "system", "content": "你是一位乐于助人的中文助手，回答简洁清晰。"},
        {"role": "user", "content": "请用一句话介绍一下什么是 LangChain。"},
    ]
)
print(response.content)
```

## 定义工具

用 `@tool` 装饰器把函数变成模型可以调用的工具。
**函数名、docstring、参数名与参数说明都会进入模型的提示词**，
所以描述要写清楚，中文描述能让模型更准确地调用。

```python
from langchain.tools import tool

WEATHER_DATA = {
    "北京": {"weather": "晴", "temperature": "26℃", "humidity": "35%", "wind": "西北风 3 级"},
    "上海": {"weather": "多云", "temperature": "29℃", "humidity": "62%", "wind": "东南风 2 级"},
}


@tool
def get_weather(city: str) -> str:
    """查询指定城市的实时天气信息。

    Args:
        city: 需要查询的城市名称，使用中文，例如 "北京"。

    Returns:
        以中文描述的天气情况，包含天气现象、温度、湿度与风力；
        若该城市没有收录数据，则返回相应的提示信息。
    """
    city = city.strip()
    for name, info in WEATHER_DATA.items():
        if name == city or name in city:
            return f"{name}当前天气：{info['weather']}，气温 {info['temperature']}，..."
    return f"抱歉，暂时没有收录「{city}」的天气数据，可查询的城市有：..."
```

这里用内置的模拟数据，保证示例离线也能跑通；
真实项目中把函数体换成调用第三方天气 API 即可。

## 创建智能体

`create_agent` 是 LangChain 1.x 的统一入口，把模型、工具、系统提示词组装起来：

```python
from langchain.agents import create_agent

SYSTEM_PROMPT = """你是一个中文智能助手，可以使用天气查询工具获取城市的实时天气。

行为要求：
1. 当用户询问天气时，必须调用 `get_weather` 工具获取真实数据，不要凭空猜测。
2. 回答时使用中文，先给出结论，再补充关键细节。
3. 如果工具没有返回数据，如实告知用户，不要编造。
"""

agent = create_agent(
    model=model,
    tools=[get_weather],
    system_prompt=SYSTEM_PROMPT,
)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "北京今天的天气怎么样？"}]}
)
print(result["messages"][-1].content)
```

### 观察完整执行轨迹

`result["messages"]` 记录了智能体的每一步，这是理解智能体行为的关键：

```
[human] 北京今天的天气怎么样？
[ai] 调用工具 get_weather，参数：{'city': '北京'}
[tool] 北京当前天气：晴，气温 26℃，相对湿度 35%，西北风 3 级。
[ai] 北京今天天气晴朗。具体来看，当前气温 26℃……
```

可以看到完整的 **human → ai(工具调用) → tool → ai** 循环，
最终答案完全基于工具返回的数据。

## 会话记忆

加上 checkpointer 就能实现多轮对话。相同 `thread_id` 共享同一份历史：

```python
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(
    model=model,
    tools=[get_weather],
    system_prompt=SYSTEM_PROMPT,
    checkpointer=InMemorySaver(),
)

config = {"configurable": {"thread_id": "demo-thread"}}

# 第一轮
agent.invoke(
    {"messages": [{"role": "user", "content": "帮我查一下魔都的天气。"}]},
    config=config,
)

# 第二轮不再提城市名，智能体依然知道「魔都」指上海
agent.invoke(
    {"messages": [{"role": "user", "content": "那这里的湿度呢？"}]},
    config=config,
)
```

实测输出：

```
=== 第一轮 ===
上海当前天气：多云，气温 29℃，相对湿度 62%，东南风 2 级。

=== 第二轮 ===
上海的相对湿度是 62%。
```

> [!TIP]
> `InMemorySaver` 只存在内存里，进程结束就没了。生产环境请换成
> `SqliteSaver` / `PostgresSaver` 等持久化实现。

## 流式输出

`stream` 配合 `stream_mode="messages"` 可以逐字输出：

```python
from langchain_core.messages import AIMessageChunk

for chunk, _metadata in agent.stream(
    {"messages": [{"role": "user", "content": "上海和深圳哪个更热？"}]},
    stream_mode="messages",
):
    if isinstance(chunk, AIMessageChunk):
        content = chunk.content
        if isinstance(content, str) and content:
            print(content, end="", flush=True)
```

这里有两个坑：

1. `stream_mode="messages"` 产出的是 **(消息片段, 元数据)** 二元组，
   直接读 `chunk.content` 会拿到空字符串——必须先解包。
2. 工具结果是以 `ToolMessage` 形式混入流的，
   要用 `isinstance(chunk, AIMessageChunk)` 过滤掉，否则工具返回的原始数据会
   混进给用户看的文本里。

## 结构化输出

用 Pydantic 定义 schema，模型返回的就是可以直接取字段的对象：

```python
from pydantic import BaseModel, Field


class WeatherReport(BaseModel):
    """一份结构化的天气报告。"""

    city: str = Field(description="城市名称")
    weather: str = Field(description="天气现象，例如「晴」「多云」「雷阵雨」")
    temperature: str = Field(description="温度，例如「26℃」")
    humidity: str = Field(description="相对湿度，例如「35%」")
    suggestion: str = Field(description="给出行人的简短建议")


structured_model = model.with_structured_output(WeatherReport)
report = structured_model.invoke("请把下面这段天气信息整理成结构化天气报告：\n杭州当前天气：晴，气温 28℃……")

print(report.city)            # 杭州
print(report.model_dump_json(indent=2))
```

### 踩坑：结构化输出与工具不能放进同一次请求

`create_agent` 也支持直接传 `response_format`：

```python
agent = create_agent(
    model=model,
    tools=[get_weather],
    response_format=WeatherReport,
)
```

但在百炼上这样写会**稳定失败**，报错如下：

```
Error code: 400 - <400> InternalError.Algo: An error occurred in model serving,
error message is: [grammar validation or compilation failed:
sandbox grammar compile timed out]
```

排查过程：

| 组合 | 结果 |
| --- | --- |
| 无工具 + `response_format` | ✅ 正常 |
| 有工具 + `response_format`，单轮 | ⚠️ 时好时坏 |
| 有工具 + `response_format`，多轮（带历史） | ❌ 稳定失败 |

原因是百炼的结构化输出基于**语法约束解码（grammar-constrained decoding）**，
需要在服务端把 JSON Schema 编译成语法。把工具 schema 和结构化 schema 放在一起、
再加上历史消息，语法编译就会超过沙箱的时间限制。

> [!TIP]
> 显式指定 `ProviderStrategy` 也解决不了，它会换成另一种报错：
> `StructuredOutputValidationError`。

**解决办法**是拆成两步——智能体带工具自由作答，再用独立的
`with_structured_output` 调用整理结果：

```python
agent = create_agent(
    model=model,
    tools=[get_weather, search_knowledge_base],
    system_prompt=SYSTEM_PROMPT,
    checkpointer=InMemorySaver(),
)

# 第一步：智能体带工具、带着记忆，自由作答
result = agent.invoke(
    {"messages": [{"role": "user", "content": "请介绍一下杭州，并给出三条出行建议。"}]},
    config={"configurable": {"thread_id": "demo"}},
)
answer = result["messages"][-1].content

# 第二步：单独一个结构化调用整理答案
structured_model = model.with_structured_output(CityBrief)
brief = structured_model.invoke(f"把下面这段城市介绍整理成结构化结果：\n{answer}")

print(brief.city)
for tip in brief.tips:
    print(f"  - {tip}")
```

这个模式拆开之后稳定可用，实测连续 3 次全部成功。

## 错误重试

百炼偶发服务端临时错误，示例里加了一层只针对临时错误的重试：

```python
TRANSIENT_ERROR_MARKERS = (
    "grammar validation or compilation failed",
    "sandbox grammar compile timed out",
    "InternalError.Algo",
    "ServiceUnavailable",
    "Throttling",
    "RequestTimeOut",
)


def is_transient_error(exc: BaseException) -> bool:
    """判断异常是否为可重试的服务端临时错误。"""
    return any(marker in str(exc) for marker in TRANSIENT_ERROR_MARKERS)


def with_retry(func, *, max_attempts: int = 3, delay: float = 2.0, backoff: float = 2.0):
    """带指数退避的重试包装，只对服务端临时错误重试。"""
    wait = delay
    for attempt in range(1, max_attempts + 1):
        try:
            return func()
        except Exception as exc:
            if not is_transient_error(exc) or attempt == max_attempts:
                raise
            time.sleep(wait)
            wait *= backoff
```

关键是**只对临时错误重试**：`ValueError` 这类业务异常必须立即抛出，
否则真实的参数错误会被重试 3 次才失败，掩盖问题。

## 总结

LangChain 1.x 的 API 收敛得相当彻底，官方快速开始只需要三样东西：
**模型 + 工具 + `create_agent`**。但从示例到可用代码，中间还有几个必须注意的点：

1. **百炼接入**用 `init_chat_model("openai:...")`，别再叠加 `model_provider`。
2. **工具描述要写清楚**，它会直接进入提示词，中文描述效果更好。
3. **流式输出要解包二元组**，并过滤掉 `ToolMessage`。
4. **结构化输出与工具不要共用一次请求**，百炼的语法编译扛不住。
5. **临时错误要重试**，但只重试临时错误。
